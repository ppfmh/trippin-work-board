Handoff 예시 · 카페 주문 화면 (음료 옵션)

TripPin과 상관없는 예시예요(5번은 「이전 시안보다」로 바꿔 적었어요). 칸마다 이 정도로 적으면 개발자가 디자인을 열어 보지 않아도 화면을 만들 수 있어요. 숫자 · 조건 · 다음 화면을 구체적으로 쓰는 게 핵심이에요.

1. 이 화면은 무엇인가요

카페 앱에서 고른 음료의 옵션(사이즈 · 샷 · 얼음)을 정하고 장바구니에 담는 화면이에요.

2. 언제 나타나나요

메뉴 목록에서 음료 카드를 누르면 열려요. 장바구니에서 담은 음료의 「옵션 변경」을 눌러도 같은 화면이 열리고, 이때는 고른 옵션이 미리 선택돼 있어요.

3. 동작 규칙

• 사이즈를 바꾸면 가격이 바로 바뀌어요 (Tall 4,500원 · Grande +500원 · Venti +1,000원).
• 샷 추가는 1개당 +500원, 최대 3개까지. 3개가 되면 + 버튼이 비활성으로 바뀌어요.
• 수량을 바꾸면 아래 「담기」 버튼의 금액이 (음료 가격 × 수량)으로 바뀌어요.
• 「담기」를 누르면 「장바구니에 담았어요」 토스트가 뜨고 메뉴 목록으로 돌아가요. 위쪽 장바구니 숫자가 1 늘어요.
• 품절인 옵션은 회색으로 보이고 누를 수 없어요.
• 엣지케이스: 음료 이름이 길면 두 줄까지 보이고 나머지는 … 처리.

4. 디자인 결정 이유

• 가격을 「담기」 버튼 안에 넣었어요. 옵션을 바꿀 때마다 눈이 가는 곳에서 금액이 바뀌어야 실수로 비싼 옵션을 담지 않아요.
• 사이즈는 셀렉트 대신 칩 3개로 했어요. 고를 게 세 개뿐이라 한눈에 보이는 게 빨라요 (결정 기록 11.24).
• 샷 최대 3개는 매장 정책이에요. 막힌 이유를 알 수 있게 + 버튼 아래에 「최대 3샷」을 작게 적었어요.

5. 이전보다 나아진 점

• 이전 시안은 옵션을 바꿔도 가격이 그대로였어요. 이제 사이즈 · 샷 · 수량에 따라 「담기」 금액과 장바구니 숫자가 바로 바뀌어요 (화면끼리 값이 이어짐).
• 쓰지 않던 색 토큰 12개를 빼고, 이 화면에 쓰는 것만 남겼어요.
• 「담기」를 누른 뒤 어디로 가는지 없던 것을 메뉴 목록 + 토스트로 정했어요.

작업 방식 및 순서

  1. 프롬프트 던지기Claude Code에서 레포 ppfmh/trippin-work-board 를 고르고(Figma 연결도 켜고) 새 대화를 열어요. 맨 아래 「시작 프롬프트」를 복사해 붙여 넣고, [Figma 링크]를 채워 보내요. Claude가 레포의 보드 파일을 읽고 규칙대로 시작하고, 고친 것은 레포에 올려요. 이 링크에는 팀장 쪽에서 1시간 안에 반영돼요. 다음 날 새 대화로 이어서 할 때도 같은 프롬프트를 붙여 넣으면 어디까지 했는지 알려 주고 이어서 해요.
  2. 토큰Claude가 Figma 변수를 토큰으로 옮겨요. 이상한 이름 · 겹치는 값은 선택 창으로 물어요. 고르고 이유를 한 줄 말하면 결정 기록에 그대로 남아요. 화면과 컴포넌트 변형에서 안 쓰는 토큰은 빼요.
  3. 컴포넌트DS 컴포넌트를 변형(hover · pressed · selected · focus · disabled …)까지 전부 넣어요. Figma 섹션대로 Input · Selection · Display · Feedback · Navigation 묶음으로 정리되고, 디자인 시스템 탭 왼쪽 목록에서 볼 수 있어요.
  4. 디자인 시스템 확인디자인 시스템 탭을 직접 보고 「확인했어」라고 말해야 화면을 시작해요. 이상하면 이때 고쳐 달라고 하세요.
  5. 화면 만들기Figma 화면 링크를 하나씩 주면 한 화면씩 만들어요. 컴포넌트를 써서 마우스 올림 · 누름이 Figma대로 바뀌어요. Figma에서 DS가 아닌 요소는 그대로 만들고 「DS 아님」으로 표시돼요. 고칠지는 민철님이 정해요.
  6. 동작 지시"이 버튼 누르면 일정 화면"처럼 말로 지시해요. 이동할 화면 · 상태 · 문구가 Figma에 없으면 Claude가 선택 창으로 물어요. 5차 화면들이 값과 흐름으로 이어지게(합계 · 위쪽 요약 · 저장 뒤 상태) 만드는 게 목표예요.
  7. 엣지케이스화면마다 비어 있음 · 긴 글자 · 오류 · 불러오는 중 · 겹침 등을 선택 창으로 물어요. 추가하면 그 화면 아래 「엣지」 탭으로 보여요.
  8. 확인하고 고치기「프로토타입으로 보기」 · 「전체 화면으로 보기」로 처음부터 끝까지 눌러 봐요. 인스펙터로 하드코딩 · DS 아님을 직접 찾아 「이 요소의 이 값을 이렇게」 하나씩 말해요. "다 찾아서 없애줘", "한번에 알아서 다 고쳐줘"는 거절해요. 직접 발견한 건 언제든 고쳐 달라고 하면 돼요.
  9. 디자인 다듬기포트폴리오로 쓸 수 있게 디자인 시스템과 화면을 고쳐도 돼요. 디자인 시스템을 먼저 고치고 화면에 적용하고, Figma와 달라진 점과 이유는 결정 기록에 남아요.
  10. Handoff 쓰기화면마다 오른쪽 「Handoff」에 5칸을 직접 써요(무엇 · 언제 · 동작 규칙 · 결정 이유 · 5차보다 나아진 점). Claude는 대신 써 주지 않아요. 「예시 보기」를 참고하세요.
  11. 제출 전 점검아래 「제출할 것」을 하나씩 체크해요. 늦어질 것 같으면 11.27 전에 「한 것 · 남은 것」을 먼저 알려 주세요.

시작 프롬프트 · Claude Code에 붙여 넣기

Claude Code에서 레포 ppfmh/trippin-work-board 를 고르고 Figma 연결을 켠 새 대화 맨 처음에 붙여 넣고, [Figma 링크]만 채워요.

너는 신민철(주니어 디자이너)과 함께 TripPin 일정 화면을 동작하는 HTML 프로토타입으로 만드는 파트너야. 작업 장소는 GitHub 레포 ppfmh/trippin-work-board 의 board.html(작업 보드)이고, 먼저 그 파일과 CLAUDE.md 를 읽은 뒤 맨 위 「Claude에게」 주석의 규칙을 그대로 따른다. 코드는 네가 쓰지만 디자인과 동작 결정은 전부 민철이 한다.

[자료]
- 작업 보드(원본): 레포 ppfmh/trippin-work-board 의 board.html
- 보드 보기(팀장님과 같이 보는 링크): https://claude.ai/artifact/Pi7Fvha6sZdYT568943z2R
- Figma 파일: [Figma 링크]
- 범위: 5차 과제에서 그린 화면 전부. 화면끼리 값과 흐름이 이어지게 만든다. 새 화면 · 새 기능은 만들지 않고 필요하면 묻는다

[순서]
1. 순서는 토큰 → 컴포넌트(변형 전부) → 민철 확인 → 화면. 디자인 시스템 먼저: Figma 변수(색·글자·간격·모서리)를 style#ds 에 --ds- 토큰으로, DS 컴포넌트를 section#ds-components 에 data-ds="이름" 으로, 변형(hover·pressed·selected·focus·disabled 등) 전부를 변형 × 상태 표로 넣는다. 카드마다 data-ds-group 을 Figma components 섹션대로 Input · Selection · Display · Feedback · Navigation(제품 전용 섹션은 맨 뒤) 중 하나로 붙이고, 묶음 순서대로 · 묶음 안은 작은 것부터 놓는다. 이름·값은 Figma 그대로. 「안 쓰는 토큰」은 화면과 컴포넌트 변형을 함께 보고 정한다. 이상한 이름이나 같은 뜻 두 값은 목록으로 보여 주고 Figma를 고칠지 묻는다. 민철이 확인하기 전에는 화면을 만들지 않는다.
2. 화면 구성: 민철이 「확인했어」라고 한 뒤에 시작한다. 민철이 주는 Figma 화면 링크 순서대로 한 화면씩, 그 컴포넌트로 만들어(프로토타입에서 hover·누름·포커스가 변형대로 바뀌게) <section class="screen" data-screen="번호" data-title="이름"> 으로 만든다. --ds- 토큰만 쓴다. 고칠 자리는 글자가 아니라 실제 태그 줄로 찾고, 고친 뒤 보드가 정상인지 확인한다.
3. Figma에서 DS 컴포넌트가 아닌 요소는 DS로 바꾸지 말고 그대로 구현한다. data-figma="레이어 이름" 만 붙이고 data-ds 는 붙이지 않는다.
3-1. 보드에 불러온 디자인 시스템과 화면은 민철이 고쳐도 된다(마무리 과제, 포트폴리오용). 민철이 말하면 고친다. 화면은 디자인 시스템 기준으로 고치고(새 값은 토큰·컴포넌트부터), 네가 먼저 고치자고 하지 않는다. Figma와 달라진 점과 민철의 이유를 결정 기록에 그대로 남긴다.
4. 동작은 민철이 말로 지시한 대로 만든다. 화면 이동은 data-go="화면 번호", 그 밖의 동작은 <script id="proto-js"> 에.
5. 엣지케이스: 한 화면을 만들 때마다 생길 수 있는 엣지케이스(비어 있음, 아주 긴 글자, 최대·0, 오류, 불러오는 중, 겹침 등)를 목록으로 보여 주고, 하나씩 추가할지와 어떻게 보일지 선택 창으로 선택지 + 「추가 안 함」 + 「기타」를 주고 묻는다. 추가하면 <section class="edge" data-of="화면 번호" data-edge="영문 id" data-title="이름"> 으로 만든다.

[빠진 것은 묻는다]
- 이동할 화면·과정·상태·요소·문구·값이 Figma에 없으면 스스로 설계하지 말고 "○○이(가) 없습니다. 어떻게 할까요?"로 묻는다.
- 질문은 채팅에 늘어놓지 말고 선택 창(AskUserQuestion)으로 한 번에 하나씩 묻는다. 선택지 2–3개 + 「기타」. 추천하지 않는다.
- 고른 뒤 "왜 이걸 골랐어요?"를 한 줄로 묻고, 답을 결정 기록(id="decisions")에 민철의 말 그대로 남긴다. 답을 받기 전에는 그 부분을 만들지 않는다.
- 보고는 두세 줄로 짧게. 자세한 건 보드(디자인 시스템 탭 · 결정 기록)에서 보게 한다.
- 결정 기록에는 민철이 고르거나 말한 것만 민철의 말 그대로 적는다. 요약하거나 바꿔 쓰지 않는다. 묻지 않고 정하지 않는다.
- Handoff는 민철이 화면마다 직접 쓴다. 대신 써 주지 않는다.

[거절한다]
- "하드코딩 다 찾아서 없애줘", "DS 아닌 거 전부 바꿔줘", "한번에 알아서 다 고쳐줘" 같은 요청은 하지 않는다. 민철이 인스펙터로 직접 찾아 요소와 값을 하나씩 말하게 한다. 짚어 준 것은 고친다.
- 네가 묻지 않은 것이라도 민철이 스스로 발견해 고치자고 하면 고친다(디자인 시스템 기준, 결정 기록에 이유).
